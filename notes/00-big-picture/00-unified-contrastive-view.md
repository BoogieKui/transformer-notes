# 洞察笔记：推荐、分类聚合、word2vec 是同一台引擎

> 这是一篇跨章节的"骨架"笔记——不是某个 lecture 的内容，而是把一条贯穿始终的线提前抽出来。你后面在 Attention、对比学习（CLIP/SimCLR）、GPT 里会反复撞见它。
>
> 起因：学负采样（`01-word-vectors/01-word2vec.md` 第 12 节）时，注意到"推荐算法、分类聚合、word2vec 好像有内在联系"。这个直觉是对的，本文把它讲清楚。

## 1. 推荐系统在做什么：矩阵分解

经典"协同过滤"推荐，问题长这样：

| | 玩具总动员 | 阿凡达 | 星际穿越 | 泰坦尼克 |
|---|---|---|---|---|
| Alice | 看了✓ | 看了✓ | ？ | |
| Bob | | 看了✓ | 看了✓ | |
| Carol | | | | 看了✓ |

**问号就是要预测的东西**："Alice 会不会喜欢 星际穿越？"

做法叫**矩阵分解（matrix factorization）**：把每个用户、每部电影都压成一个低维向量，预测打分 = 两个向量点积：

$$
\text{score}(\text{Alice} \to \text{星际穿越}) = \mathbf{p}_{\text{Alice}} \cdot \mathbf{q}_{\text{星际穿越}}
$$

$\mathbf{p}_{\text{Alice}}$ 是"Alice 的口味向量"，$\mathbf{q}_{\text{星际穿越}}$ 是"这部电影的特征向量"。

## 2. word2vec 就是同一个东西

把名字换一下：

| 推荐系统 | word2vec |
|---|---|
| 用户 Alice | 中心词 "sat" |
| 电影 星际穿越 | 上下文词 "on" |
| "看过" | "在窗口里一起出现过" |
| p_Alice · q_movie | v_sat · u_on |

**一模一样。** word2vec 在对一个"词 × 词共现矩阵"做矩阵分解，推荐系统在对"用户 × 电影交互矩阵"做矩阵分解。

> 这不是类比，是**同一个东西**。Levy & Goldberg（2014）严格证明：负采样 skip-gram 的最优解，等价于把"点互信息（PMI）矩阵"做低秩分解（差一个 log k 偏移）。而 PMI 矩阵就是"词-词共现"的某种归一化——和用户-物品矩阵是同一类对象。

## 3. 负采样 = 隐式反馈

你刚学完的负采样，推荐里几乎原封不动在用，只是换了个名字：**隐式反馈（implicit feedback）**。

关键问题一样：你只有**正信号**——Alice 看了这部电影（像 "on" 出现在 "sat" 旁），但**没有负信号**——她从没说过"我讨厌这部电影"。大多数用户×物品格子是空的，你不知道是"不喜欢"还是"没看到"。

于是**采负样本**：训练时拿 Alice 看过的电影当正例，随机抽几部她没看过的当负例，让模型"正例打分高、负例打分低"。这就是 word2vec 的负采样，一字不差。

**连 3/4 次方都有对应物**：推荐里均匀抽负样本会抽出大量冷门电影（=低频词），按热度抽又全是头部爆款（= "the" 霸占一切）。所以推荐也有"流行度加权采样"，和 word2vec 的 count^0.75 是同一个动机——压平幂律长尾。YouTube 2016 的推荐论文，就直接对几百万视频用采样 softmax/负采样——"词表"换成了"视频库"，同一个"词表太大"问题。

## 4. "分类 + 聚合"：softmax / sigmoid / 负采样

| 操作 | 在做什么 | 有没有"聚合" |
|---|---|---|
| softmax | 在 \|V\| 个类里挑一个 | 有：所有类 exp 求和做分母 Z（全量聚合） |
| sigmoid | 每个候选独立判真/假 | 无：不要求概率和为 1 |
| 负采样 | 只抽 k 个候选来判 | 有，但是**抽样**聚合（蒙特卡洛，见 `01-word-vectors/appendix-monte-carlo.md`） |

"分类"是目标（把正确的类找出来），"聚合"是代价（让所有类概率和为 1 的分母）。**负采样 = 把"全量聚合"换成"抽样聚合"。**

## 5. 更广的视野：对比学习（CLIP / SimCLR）

这套骨架再往前一步，就是现代"对比学习"：

- 喂"词-词共现" → word2vec
- 喂"用户-物品交互" → 推荐
- 喂"图片-它的文字描述" → CLIP

它们全是同一句咒语：**从"共现/交互"数据里，用"正负对比"学出低维嵌入，再用"归一化"把分数变成概率。** 这条线一路贯穿到 GPT 的预训练里（"预测下一个词"本质也是一种自监督的对比/分类）。

## 6. 一句话总结

> **推荐、分类聚合、word2vec（以及后面的对比学习）是同一台引擎的三张脸：用"正负对比"从共现数据里学嵌入，再用"归一化"把分数变成概率。**
>
> 换的只是燃料（词共现 / 用户交互 / 图文对），引擎不变。
