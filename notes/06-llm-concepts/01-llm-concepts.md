# 06 LLM 关键概念：Transformer 之后

> 学完 Transformer，我们手上是一个只会"给定前文、预测下一个 token"的模型。训练完成后反复执行这个过程，就能生成一段文本——这为现代自回归 LLM 提供了重要的基础。
>
> 阶段 5（`../05-pretraining/`，四篇）已经把这个起点讲透了：**next-token prediction 是唯一一个"训练时在做的"和"用的时候要做的"字面相同的目标函数**——所以它不需要 `[MASK]`、不需要任务头、不需要先攒一批标注数据，就能直接拿来用（`../05-pretraining/04-why-decoder-only.md` §2）。
>
> 但它后来是怎么变成今天能回答问题、能做多步推理、能调用工具、能看图听声的 LLM 的？
>
> 这一篇不按技术名词、也不按论文出现的顺序介绍，而是**按一个核心问题展开**：一个只会预测下一个 token 的 Transformer，究竟经过了哪些发展，才变成今天这样的 LLM？

---

## 0. 从一台续写机器开始

给定一段已经出现的 token，模型根据前面的内容，预测下一个 token 的概率分布。训练完成后，我们反复执行这个过程，就可以生成一段文本。

**但现在的问题是：** 预测下一个 token，如何发展成回答问题、解决数学题、编写代码、调用工具，甚至理解图像和语音的能力？

答案不是某一项神奇的新技术，而是**多个方向共同发展**。为了理解它们，我们需要依次回答几个问题：

1. 如何训练出更强的基础模型？
2. 如何让模型按照人类的要求行动？
3. 如何提高模型解决复杂问题的能力？
4. 如何降低模型的计算成本？
5. 如何让模型使用外部知识和工具？
6. 如何让模型处理文本之外的信息？
7. 如何判断这些能力是否真正可靠？

---

## 1. Scaling Laws：模型为什么会随着规模增长而变强？

**Scaling Laws，即规模定律，研究的是模型规模、数据规模、计算投入与模型性能之间的经验关系。**

### 核心问题

如果想让模型变得更强，最直接的方法是什么？

一个自然的想法是增加参数量。更大的模型拥有更多可学习的参数，通常能够拟合更复杂的模式。但是，模型并不是越大越好，因为训练模型还需要足够的数据和计算资源。

这里出现了三个相互关联的变量：

- **模型规模**：模型有多少参数。
- **训练数据**：模型接触了多少 token。
- **训练算力**：完成训练需要多少计算。

### 最重要的认识

在固定的训练算力预算下，你必须决定把资源分配到哪里：**是训练一个更大的模型，还是训练一个相对较小、但接触更多数据的模型？**

2022 年的 Chinchilla 研究给出了一个有影响力的答案：在其研究的训练条件下，许多大型模型使用的训练数据相对于参数量而言并不充分。研究者用与 Gopher 相近的训练算力，训练了一个参数量更小、数据量更大的模型，发现它在多项评估中取得了更好的表现。

这项工作的意义，**并不是告诉我们永远应该使用某个固定的数据与参数比例**。它真正说明的是：

> **模型容量和训练数据需要协调增长。只增加参数，并不保证在有限预算下获得最好的结果。**

### 进一步的问题

规模定律并没有告诉我们所有答案。

即使模型规模和数据量都很大，结果仍然取决于**数据质量、训练方法以及具体的能力目标**。因此，训练更强的模型不仅仅是收集更多数据，还涉及数据筛选、去重、配比和质量控制。

合成数据也属于这个更大的问题：**我们能否构造高质量的训练样本，让模型学会现实数据中较少出现的技能？**

> **这一部分需要记住的结论：模型能力取决于模型规模、数据、训练方法和计算投入之间的共同作用。**

## 2. Post-training：如何让模型从续写文本变成遵循指令的助手？

### 核心问题

预训练模型学习的主要任务，是根据前文预测下一个 token。

但是，**预测互联网上最可能出现的后续文本，与按照用户的要求给出有用的回答，并不是同一件事**。

例如，用户问：

> "请解释什么是光合作用。"

一个只经过预训练的模型，可能延续成一段百科内容，也可能输出一份教案、一道考试题，或者一段与问题有关但没有直接回答问题的文字。**它能生成这些内容，不代表它已经学会了如何成为一个好的助手。**

这就是**后训练**（post-training）要解决的问题。

### 第一种方法：SFT

**SFT 是 supervised fine-tuning，即监督微调。**

最直观的做法是准备大量示范：给定一个问题，展示理想的回答；然后继续训练模型，让它更倾向于生成类似的回答。

这里不需要改变 Transformer 的基本结构。它仍然可以使用 next-token prediction，只是训练数据变成了大量指令和理想回答。**SFT 教会模型的，是如何按照示范处理任务。**

### 第二种方法：学习人类偏好

但示范数据有一个问题：**我们很难为所有问题预先写出唯一正确的答案。**

于是，人们可以让标注者比较几个候选回答，判断哪个更好。例如，两个回答都正确，但一个更清楚、更符合要求，另一个冗长而且遗漏了关键信息。这些偏好可以用来进一步训练模型。

**RLHF 是 reinforcement learning from human feedback，即基于人类反馈的强化学习。** InstructGPT 的经典方案先用示范数据进行监督微调，再利用人类对回答的偏好进行后续优化。

此外，**DPO**（direct preference optimization，直接偏好优化）等方法提供了不同的偏好优化方案。理解这个领域时，不必把某一种训练流水线当成唯一标准。

### 最重要的认识

预训练与后训练侧重解决不同的问题。**预训练主要建立广泛的语言与任务能力；后训练进一步调整模型如何响应指令、遵循约束和满足特定的行为要求。**

但是，这种划分不是绝对的。后训练也能带来新的技能，预训练也会影响模型的行为。

还有一个重要边界：**人类偏好只是训练信号，不是真理本身。** 人类可能判断错误，奖励模型也可能学到不理想的偏好。

> **这一部分需要记住的结论：拥有生成能力，与知道什么样的回答才符合任务要求，是两个不同的问题。**

## 3. Reasoning：如何提高模型解决复杂问题的能力？

这是现代 LLM 发展中最值得单独理解的方向之一。

### 3.1 从直接回答到分步骤解决问题

想象一道需要多个步骤的数学题。如果模型直接生成最终答案，它可能在某个中间步骤出错，导致最终结果错误。一个自然的改进方式，是**让模型先写出中间步骤，再得出答案**。

这就是 **Chain of Thought**，简称 **CoT**，即思维链。

思维链提示的一种经典方法，是在 prompt 中提供几个带有推理过程的示例，引导模型用类似的方式解决新问题。

但这里需要注意：

> **让模型输出推理步骤，不等于保证模型真正完成了可靠的推理。** 一段推理文字可能逻辑正确，也可能只是看起来有条理，实际却包含错误。

CoT 首先是一种**改善任务表现的提示方法**，而不是关于智能本质的完整解释。

### 3.2 从提示方法到推理训练

如果我们希望模型稳定地处理更复杂的问题，仅仅依赖提示词可能不够。另一条路径是**直接训练模型，使其更擅长多步推理**。

例如，在数学和编程任务中，我们往往能够检验最终结果是否正确。模型可以尝试不同的解法，再根据结果或其他奖励信号调整自己的行为。这就把**强化学习**引入了推理能力的训练。

在 DeepSeek-R1 的研究中，研究者探索了通过强化学习激励推理能力的方式。它展示了一条重要路线：**不只让模型模仿现有的答案和推理过程，还可以通过奖励机制优化模型解决问题的行为。**

其中一个重要概念是 **RLVR**，即 reinforcement learning with verifiable rewards，使用可验证奖励的强化学习。它的关键在于：**当答案能够被程序、数学规则或测试用例验证时，我们就获得了一种比单纯的主观偏好更明确的反馈信号。**

当然，这并不意味着所有问题都能被自动验证。数学题和代码中的可验证结果，与开放式写作或复杂现实判断，具有不同的评价条件。

### 3.3 Test-time Compute：为什么推理时多花计算可能带来更好的答案？

传统上，我们常常把模型训练视为提高能力的主要途径。但还有另一种思路：**模型训练完成之后，也可以通过投入更多推理计算，改善某些任务的表现。**

这被称为 **test-time compute，即推理时计算**。

例如，模型可以生成更长的解题过程，尝试多个候选方案，检查中间结果，或者进行更多轮的搜索与验证。

OpenAI 关于 o1 的早期研究明确讨论了两个不同的扩展方向：**增加强化学习训练投入**，以及**增加模型推理时使用的计算**。研究观察到，模型性能能够随着这两种投入增加而改善。

这里需要区分两个概念：

- **训练时计算**：用于改变模型参数，让模型学到更有效的行为。
- **推理时计算**：模型回答具体问题时额外使用的计算资源。

前者试图让模型**在未来更擅长解决问题**；后者试图让模型**在眼前的这个问题上表现得更好**。两者都需要付出成本，而且增加计算并不保证表现一定提高。

> **这一部分需要记住的结论：现代推理模型的发展，不仅依赖训练更强的模型，也依赖让模型在解决具体问题时更有效地使用计算。**

## 4. Efficiency：为什么模型越强，部署它就越困难？

模型越大，通常需要存储的参数就越多，计算成本也越高。但实际运行 LLM 时，**参数量并不是唯一需要考虑的指标**。我们还要考虑显存、带宽、延迟、吞吐量，以及每次生成 token 的实际成本。

因此，LLM 的发展不仅在追求更强的能力，也在不断寻找更有效的计算方式。

### 4.1 MoE：不让每个 token 都经过所有参数

传统的稠密 Transformer 中，每个 token 通常都会经过网络中的各个前馈网络层。这意味着，如果我们不断增加模型中的前馈网络参数，单个 token 的计算成本也会随之上升。

**MoE，即 mixture of experts，专家混合，提供了另一种思路。** 它把一个前馈网络替换为多个专家网络，并使用路由机制为每个 token 选择其中一部分专家。

因此，**模型可以拥有大量参数，但每个 token 只使用其中的一部分**。

例如，DeepSeek-V3 技术报告中的模型具有 671B 总参数，每个 token 激活的参数约为 37B。

这里必须区分：

- **总参数量**：描述整个模型的参数规模。
- **激活参数量**：描述处理某个 token 时实际参与计算的参数规模。

MoE 并没有让模型完全摆脱成本。未被激活的专家仍然需要存储，路由和设备之间的数据传输也会带来开销。**它改变的是模型容量与每个 token 的计算量之间的关系。**

### 4.2 KV Cache：为什么模型需要记住之前处理过的内容？

自回归模型生成文本时，每次生成一个新 token，都需要参考之前的上下文。

在 Transformer 中，**KV cache（key-value cache，键值缓存）**会缓存历史 token 在注意力机制中计算得到的 Key 和 Value。这样，模型在继续生成时，就不必为所有历史 token 重复计算这些表示。

但 KV cache 自身也需要内存，而且通常会随着上下文长度和生成过程增长。因此，**长上下文不仅仅是一个模型能力问题，也是一项内存和推理成本问题。**

### 4.3 Attention 优化：减少计算过程中的浪费

还有一类优化并不试图改变模型学到什么，而是试图**更有效地执行相同或相近的计算**。

**FlashAttention** 就是一个重要例子。它通过优化注意力计算的数据读取、临时结果存储和 GPU 并行执行方式，提高计算效率并减少内存开销。它并不是通过取消全注意力的基本计算关系来达到加速效果。

类似地，**GQA**（grouped-query attention，分组查询注意力）、**MLA**（multi-head latent attention，多头潜在注意力）等技术也可以从不同角度改善注意力相关的计算或内存开销。

### 最重要的认识

这些技术共同回答了一个问题：**如何在有限的硬件预算下，运行更强、更长上下文或吞吐量更高的模型？**

理解它们时，不必只记住某个加速倍数，而应该弄清楚**它优化的究竟是计算量、内存占用、带宽，还是设备利用率**。

> **这一部分需要记住的结论：模型能力和运行效率是两个相关但不同的优化目标。**

## 5. Context：为什么长上下文并不等于无限记忆？

上下文窗口规定了模型在一次处理过程中能够利用多少 token 的上下文。扩大上下文窗口，可以让模型在一次请求中处理更长的文档、更长的对话，或者更多相关材料。

但长上下文并没有消除所有限制。

首先，更多 token 意味着更多输入需要处理。对于常规全注意力机制，**注意力计算的基本复杂度通常随序列长度呈平方增长**；运行时还需要考虑 KV cache 等内存开销。

其次，**能够把内容放进上下文，不等于模型能够平等、准确地利用其中每一部分信息。**

因此，我们需要把三个概念分开：

- **上下文长度**：决定模型能够接触多少当前材料。
- **模型学到的知识**：取决于训练过程以及其他知识获取途径。
- **长期记忆或外部存储**：涉及如何在不同请求之间保存、检索和更新信息。

后面要讨论的 RAG，就是利用外部存储扩展模型可用信息的一种方法。

> **这一部分需要记住的结论：上下文是模型当前可利用的信息空间，不是无限容量的记忆系统。**

## 6. RAG、Tool Use 和 Agent：模型如何利用自身参数之外的能力？

仅仅依靠模型参数，并不能满足所有实际任务的需要。企业文档可能经常更新，用户也可能要求模型查询最新信息、执行计算，或者与外部软件交互。此时，可以把语言模型与外部系统结合起来。

### 6.1 RAG：先找到信息，再生成答案

**RAG 是 retrieval-augmented generation，即检索增强生成。**

最简单的工作方式是：

1. 根据用户的问题，从外部文档库中检索相关材料。
2. 把检索结果放进模型的上下文。
3. 让模型根据这些材料生成回答。

它的关键思想是：**不必把所有知识都预先存进模型参数中，也可以在回答问题时动态提供相关信息。**

原始 RAG 研究探索了将外部检索与语言生成结合的方法，并发现这种方式能够改善多种知识密集型任务中的生成表现。

但 RAG 也不是事实准确性的保证。检索可能找到错误或不相关的文档，模型也可能误读材料，或者生成超出证据范围的结论。因此，**检索质量、材料组织、答案生成和来源核查都很重要**。

### 6.2 Tool Use：让模型调用外部工具

假设模型需要计算一个复杂表达式。它可以尝试直接生成答案，也可以调用计算器，让外部程序完成计算，再根据返回结果继续回答。

这里的关键变化是，**模型不再只是生成一段最终展示给用户的文本**。它还需要决定：

- 什么时候调用工具。
- 应该选择哪个工具。
- 应该传递什么参数。
- 如何理解工具返回的结果。

Toolformer 等研究探索了如何让语言模型学习使用外部工具。这也说明，**模型的实际能力可以通过与外部程序合作得到扩展，而不必要求模型独自完成每一步操作。**

### 6.3 Agent：让模型反复行动，而不是只回答一次

如果我们把工具调用扩展为多轮过程，就可以得到更复杂的智能体系统。例如：

> 模型先制定计划，调用工具执行一个步骤，根据返回结果更新自己的判断，再决定下一步行动，直到完成任务或者达到停止条件。

这类系统通常涉及**模型、工具、执行环境、状态记录以及控制循环**。

因此，**Agent 不只是一个更长的回答，也不仅仅是更换了一种模型结构。** 它意味着：模型开始参与一个持续进行的任务过程，而不是只为单次输入生成一个输出。

这同时带来新的挑战，例如**错误行动的累积、权限控制、执行失败，以及如何判断任务是否真正完成**。

> **这一部分需要记住的结论：RAG 扩展模型可以利用的信息，工具调用扩展模型可以借助的能力，而 Agent 把这些能力组织成一个持续的任务过程。**

## 7. Multimodality：为什么 LLM 不再局限于文本？

前面讨论的大部分内容，都围绕文本展开。但现实世界的信息并不只有文本：

- **图像**包含空间结构。
- **音频**包含时间变化。
- **视频**则同时包含图像和时间信息。

要让模型处理这些数据，就需要找到适当的表示方法，并让它们与模型的计算和训练过程衔接起来。

### 图像是如何进入模型的？

一种经典的视觉 Transformer 方法，是**把图像切分成多个小块，把每个图像块转换为向量，再交给 Transformer 处理**。这样，图像可以通过类似序列建模的方式进入模型。

但要注意，**图像块并不是天然等价于普通文字 token**。视觉表示需要经过相应的编码和处理，模型也需要通过训练学会利用这些表示。

### 音频和视频呢？

音频可以通过专门的编码方法或离散 token 表示；视频则需要处理图像内容以及不同时间点之间的关系。

不同的多模态模型会采用不同的架构、表示和训练方式。例如，GPT-4o 的官方技术说明描述了一个能够接收文本、音频、图像和视频等输入，并生成多种形式输出的自回归多模态模型。

这种发展不仅扩大了模型可以接收的信息种类，也改变了人机交互的方式。用户不再只能打字提问，还可以展示图片、使用语音交流，或者提供其他类型的材料。

### 最重要的认识

**多模态不是简单地给文本模型增加一个新的输入按钮。** 它涉及数据表示、不同模态之间的对应关系、训练目标，以及不同输入和输出形式如何在一个系统中协同工作。

> **这一部分需要记住的结论：LLM 的建模思想可以扩展到文本以外，但不同模态仍然需要相应的表示方法和学习机制。**

## 8. Quantization 与 Distillation：如何让模型变小、运行得更便宜？

训练出强大的模型，并不意味着我们可以不计成本地使用它。如果模型需要消耗大量显存，推理速度又不够快，那么它在很多实际场景中就很难部署。这里有两种值得区分的技术。

### Quantization：减少数值表示的成本

**量化**通常是用较低精度的数值表示模型权重，或者在适当的方案中表示其他计算数据。例如，与 FP16（16 位浮点）相比，使用 INT8（8 位整数）表示权重可以减少权重存储所需的空间。

具体收益取决于量化方法、硬件支持和执行实现。低精度也可能影响模型表现，因此需要进行测试。

它主要关注的是：**如何减少数值表示和相关计算的成本。**

### Distillation：让较小的模型学习较大模型的能力

**知识蒸馏关注的问题不同。**

假设一个大模型能够完成某项任务，而我们希望得到一个成本更低的小模型。一种办法是让小模型学习大模型的输出或其他训练信号，使它在较小的参数规模下尽可能保留教师模型的能力。

因此，蒸馏的核心**不只是生成更多训练数据，而是利用教师模型提供的监督信号来训练学生模型**。这也不意味着学生模型必然能够完整继承教师模型的所有能力。

### 两者的区别

- **量化**主要改变**数值表示方式**，以降低内存或计算成本。
- **蒸馏**主要通过**训练**，让一个模型学习另一个模型的能力。

两者也可以结合使用。

> **这一部分需要记住的结论：更强的模型不一定是最适合部署的模型。实际系统还需要在能力、成本和可靠性之间寻找平衡。**

## 9. Evaluation：我们如何知道模型真的变强了？

前面介绍的每个方向，都需要回答同一个问题：**我们怎样判断改进是否有效？**

如果一个模型在某个测试集上得分提高了，是否就意味着它整体能力更强？**不一定。**

不同评估方法测量的是不同的能力。有些测试偏向数学，有些偏向代码，还有一些测试指令遵循、知识掌握或工具使用能力。即使两个模型的总体分数相近，它们在具体任务上的表现也可能存在很大差异。

我们还要考虑：

- 评估数据是否与训练数据存在重叠。
- 模型是否真的理解了任务，还是利用了特定测试的规律。
- 结果在不同提示词和不同样本下是否稳定。
- 模型是否能够识别自己的不确定性。
- 在工具调用、检索或多步行动的任务中，整个系统是否真正完成了目标。

因此，**模型评估并不是最后才需要考虑的一个独立步骤。它贯穿训练、后训练、推理和系统部署的全过程。**

一个可靠的改进，需要明确自己**改善了什么能力、在什么条件下改善，以及付出了什么代价**。

> **这一部分需要记住的结论：参数更多、回答更流畅、基准分数更高，都不能单独证明一个模型在所有实际任务中更可靠。**

## 10. 把整张地图重新连起来

现在，我们可以回到最初的问题：一个 Transformer 模型，经过哪些发展，才能成为现代 LLM？

可以用下面这张图概括。

**第一步：预训练建立基础能力。** 模型从大量数据中学习语言和其他模式。规模定律帮助我们研究模型、数据和计算资源如何配合。

**第二步：后训练调整行为。** SFT、偏好优化和强化学习等技术，帮助模型更好地遵循指令，并针对不同任务调整行为。

**第三步：推理方法扩展问题解决能力。** 思维链、推理训练和推理时计算，使模型能够在复杂任务中尝试更多中间步骤、搜索和验证。

**第四步：架构与系统优化降低成本。** MoE、注意力优化、KV cache、量化和蒸馏等技术，从不同角度改善容量、计算、内存和部署成本之间的权衡。

**第五步：外部系统和多模态扩展能力边界。** RAG 提供外部知识，工具调用让模型借助程序执行任务，Agent 组织持续的行动过程，多模态方法则让模型处理文本之外的信息。

最后，**评估贯穿以上所有步骤**，帮助我们判断这些改进是否真实、稳定，以及值得付出相应的成本。

这就是理解现代 LLM 最重要的一张概念地图。

> **这里没有一个单独的技术能够解释所有进步。我们看到的是训练方法、推理策略、网络架构和系统工程共同发展的结果。**

## 11. 学完之后：三个问题，一个顺序

最重要的不是记住上面这些名词，而是理解它们之间的关系。比如，你以后再看到一项新的 LLM 技术，不妨先问自己三个问题。

**第一，它改变了什么？**

它改变了模型的参数和网络结构，改变了训练数据或训练目标，改变了推理时使用计算的方式，还是改变了模型与外部系统的交互方式？

**第二，它解决了什么瓶颈？**

它是在提高模型能力、改善指令遵循、降低推理成本、扩展可利用的信息，还是提高复杂任务的成功率？

**第三，它把什么成本转移到了别的地方？**

MoE 减少了每个 token 需要激活的参数，但并不意味着所有参数都不需要存储。长上下文扩展了单次输入的信息量，却增加了计算与内存压力。推理时投入更多计算可能提高复杂任务的表现，却也可能增加延迟和费用。

> **一项技术通常不会让所有指标同时改善。理解它的价值，往往就要看它改变了怎样的权衡。**

### 下一步的学习顺序

结合你已经学完 Transformer 的情况，建议按下面的次序继续：

1. **先学 Scaling Laws 和后训练。** 前者解释基础模型是如何通过数据、参数和计算的协调而变强的，后者解释为什么一个会续写的模型还需要进一步训练，才能成为一个好用的助手。
2. **然后重点学推理模型。** 把 CoT、强化学习、可验证奖励和 test-time compute 放在一起理解。这是理解现代 LLM 能力提升路径的重要一环。
3. **接着学 MoE、推理效率和上下文。** 这里可以逐步补充工程细节，包括 KV cache、Attention 优化、量化和蒸馏。
4. **最后学 RAG、工具调用、Agent 和多模态。** 它们帮助你从单个模型走向完整的 LLM 系统。

**还有一点值得强调：这张地图不是一条严格的历史时间线。** 许多技术在时间上相互交错，也有不同的发展分支。

**你现在最需要的，不是马上阅读更多论文，而是先获得一张能够容纳新知识的地图。** 有了地图，再深入某个领域时，你就更容易判断一项新技术究竟解决了什么问题，以及它为什么重要。
