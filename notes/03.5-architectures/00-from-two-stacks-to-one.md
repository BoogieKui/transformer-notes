# 从两摞到一摞：decoder-only 是怎么被选出来的

> **这篇笔记的位置**：它夹在 `03-attention-transformer/`（2017 原版 Transformer）和 `04-karpathy-nanogpt/`（逐行读 `mini_gpt.py`）之间。
>
> 03 讲的是**为翻译设计的** Transformer：encoder 一摞、decoder 一摞、中间一座 cross-attention 的桥。
> 04 要读的 `mini_gpt.py` 是 **decoder-only**：**只有一摞**。
>
> 中间少了什么？为什么**能**少？少了之后，别的零件发生了什么连锁变化？——这篇笔记只回答这三个问题。
>
> **正文不摆代码、不给实测数字**——行号、张量形状都留给 04 笔记；全文只多一张第 7 节的"与 04 的预期对照表"。它要建立的是"这台机器为什么长这样"的框架。

---

## 0. 承接：一句话早就有了，只差下半句

03 笔记 §11 里有一句话，当时是用来解释 encoder-decoder **为什么有必要**的：

> 单 RNN 语言模型建模的是 $P(w_t \mid w_{<t})$——**同一个**语言空间里词接词，输入输出是同一个域，**天然不需要分离**。

在那个语境里，它是**反面例子**："看，不分离就只能做接龙，做不了翻译。"

**而 decoder-only 就是这句话的正面回归。** GPT（Generative Pre-trained Transformer）要做的恰恰就是 $P(w_t \mid w_{<t})$——它不要翻译，它**就要**接龙。

所以这篇笔记要讲的不是"怎么把 encoder 删掉"，而是——

> **什么任务下，"删掉 encoder"这件事本身才是对的。**

---

## 1. 判据只有一条：输入和输出是不是同一个域

### 1.1 三个家族

| 家族 | 输入 → 输出 | 骨架 | 代表 |
|---|---|---|---|
| **encoder-only** | 文本 → 标签 | 只读，**双向**（能看整句） | BERT（Bidirectional Encoder Representations from Transformers） |
| **encoder-decoder** | 一个域 → **另一个**域 | 读一摞 + 写一摞 + 一座桥 | 2017 原版 Transformer、T5（Text-to-Text Transfer Transformer） |
| **decoder-only** | 文本 → **同一**域的后续 | 只有一摞，**单向** | GPT 系列 |

判据是中间那一列：**输入和输出是不是同一个域。**

"域"在这里不是玄学，就是 03 笔记 §11.1–11.2 列的那几样：**词汇表、语法、词序**。翻译的源语言和目标语言在这三样上全都不同——所以是两个域；而"一段文本"和"它的后续"，在这三样上完全一致——所以是一个域。

### 1.2 为什么"同一个域"就是判据

回到 §11.2 的论证：翻译建模的是 $P(\text{目标句} \mid \text{源句})$，这是**两个不同空间之间的条件映射**，不是词接词。要完成这个映射，你需要：

1. **先把源句的意思抽出来**（encoder 的活）
2. **再用目标语言的规则重新表达**（decoder 的活）
3. **在中间搭一座桥**，让第 2 步能随时回头查第 1 步的结果（cross-attention 的活）

这三件事里，**没有一件是"接龙"需要的**——因为接龙根本不需要"抽出意思再重新表达"，它只需要"看上文、猜下一个"。

> **一句话**：encoder 的存在理由是"有另一条序列要读"；cross-attention 的存在理由是"要去查它"。续写任务里，输入和输出是同一条序列——**这两条理由同时失效**。

### 1.3 更深一层：一个被**主动放弃**的动机

03 笔记 §11.3 还讲了 encoder-decoder 分离的**深层动机**，那一层比"跨域映射"更根本：

> 分离 + 中间那个瓶颈，是为了**逼模型学一个"语言无关的语义表示"**——不给够通道，就逼你只传"本质"。所以上一章一直抱怨的"固定向量 $c$ 是瓶颈"，**结构上是故意的**。

现在把这个动机倒过来看 decoder-only：

> **它主动放弃了这个动机。** 它不要"语言无关的语义表示"，它要的就是"接着往下写"。

这是全篇最重要的一个判断，值得单独拎出来：

> **decoder-only 不是"简化版的 Transformer"，是一次目标函数的重新选择。**零件少了两个不是"变弱"，是"换了个任务，不再需要它们"。

### 1.4 三种架构的能力边界

判据一旦清楚，三种架构各自"做不了什么"也就清楚了：

| 架构 | 读的时候 | 做不了什么 |
|---|---|---|
| encoder-only | **双向**，每个词能看到全句 | **不能直接生成**——双向编码让位置 $t$ 的表示里已经混进了 $t$ 之后的信息，拿它去"预测下一个"就是在抄答案 |
| encoder-decoder | encoder 双向，decoder 单向 | 需要**两种数据**（源 + 目标），拿不到就只能干瞪眼 |
| decoder-only | 只能看左边，**比双向少一半上下文** | "理解"类任务要**绕**：分类不能直接出标签，得把输入包装成"文本 + 答案"的形式，再看某个位置的输出分布 |

**三行里 decoder-only 那一行最反直觉**：它读得最少（单向）、做理解任务最绕，却成了今天通吃的那一个。为什么？第 3 节会给出答案。

## 2. 零件账：删了什么，什么反而升级了

### 2.1 直接删掉的两个

**encoder 整摞。** 因为续写的输入和输出是同一条序列——**没有第二条序列需要被编码**。

**cross-attention 整座桥。** 桥的作用是让 decoder 去查 encoder 的输出。现在 encoder 没了，**桥没有对岸可通**。

顺带说清楚层结构差别：

```
原版 decoder 层：masked self-attention  →  cross-attention  →  FFN
GPT 的层：      masked self-attention  →  FFN
```

**少的那一个就是 cross-attention。**（FFN = Feed-Forward Network，前馈网络。）

### 2.2 一个反直觉的结果：mask 从"细节"变成了"承重墙"

原版里，mask（掩码）只是 decoder 三个子层中**第一个子层的一个属性**。它的作用是"翻译时别偷看还没生成的答案"——是个细节，是个补丁。

到了 decoder-only，**它变成了整台机器能否成立的前提**。理由是一条链：

- 训练目标就是"给定上文预测下一个"（第 3 节会展开）
- 如果位置 $t$ 能看到 $t+1$ 之后的内容，这个任务就退化成"抄答案"
- 损失会掉到接近 0，但模型**什么也没学到**——它学的是复制，不是预测

> **删掉两个零件，剩下的并不是原样保留——某个零件的角色被抬到了承重墙的位置。**
>
> 这是架构演进里很值得记住的一种现象：**删除会重新分配重要性。**

### 2.3 原样保留的

- **masked self-attention**——现在它成了整台机器里**唯一**的注意力
- **FFN**——逐位置加工
- **残差连接 + LayerNorm（层归一化）**
- **输出头**（把隐向量映射回词表打分）

### 2.4 换了实现的

**位置编码**——从"公式现算"换成了"查表学出来"。这是一笔独立的账，见第 5 节。

## 3. 训练流程

### 3.1 并排走一遍两条训练流程

先不谈差异，把两种架构训练时**实际发生的事**逐步走一遍。

**decoder-only（续写）——五步**

```
① 取数据    从语料里切一段连续文本，长度 T。这就是输入 x
② 造标签    同一段文本【右移一格】，就是标签 y
③ 一次前向  x 过整台机器（一摞 Block），每个位置产出对词表的打分
④ 算损失    每个位置的打分和它自己的标签算交叉熵，T 个位置取平均 → 一个标量
⑤ 反传更新  拿这个标量回传，更新参数；回到 ①，换一段文本继续
```

**encoder-decoder（翻译）——七步**

```
① 取数据        一个 batch 的平行语料：（源句, 目标句）对
② 编码源句      源句过 encoder 那一摞，得到源句的表示
                【只做一次】，做完放在那儿，后面每一步都去查它
③ 造 decoder 输入  目标句【右移一格】（开头补一个起始符）
④ 解码          decoder 每一层三步走：
                  masked self-attention —— 看自己已经生成的部分
                  cross-attention       —— 拿自己的查询，去查 ② 存下的源句表示
                  FFN                   —— 逐位置加工
⑤ 出预测        decoder 顶 → 输出头 → 每个位置对词表的打分
⑥ 算损失        每个位置的打分和目标句（原样）算交叉熵
⑦ 反传更新      同 decoder-only 的 ⑤（拿损失标量回传）
```

**逐步对照**

| | encoder-decoder | decoder-only |
|---|---|---|
| 取什么数据 | 平行语料（源句 + 目标句） | 单语文本，切一段 |
| 有没有"编码"这一步 | **有**——源句过 encoder，只做一次 | **没有** |
| 层结构 | masked self-attn → **cross-attn** → FFN | masked self-attn → FFN |
| 上下文从哪来 | 已生成部分（自己）**＋ 源句**（encoder） | 只有已生成部分（自己） |
| 标签怎么来 | 目标句原样——目标句是**另一条序列** | 同一段文本右移一格——标签**由输入自己派生** |
| 损失 | 交叉熵 | 交叉熵（一样） |

> **一句话**：decoder-only 的训练流程 = encoder-decoder **砍掉「编码源句」和「cross-attention 查询」这两步**。

注意「标签怎么来」这一行有个容易混淆的地方：**两边都是"输入右移一格得到标签"**，形式上完全一样，差别在于**移的是谁**。这一条差异本身就是 §3.2、§3.4 的全部内容。

### 3.2 差异的根：标签从哪来

这是**全部差异的源头**。

| | encoder-decoder（翻译） | decoder-only（续写） |
|---|---|---|
| 训练数据 | **平行语料**：源句 + 目标句 | **单语文本**，不需要配对 |
| 标签怎么来 | **人工标注**（人翻译出来的） | **从数据本身造**：把文本右移一格 |
| 学习类型 | 监督学习（supervised） | **自监督学习**（self-supervised） |

"右移一格"具体是什么意思——拿一段文本，**输入是它，标签是它自己往后挪一位**：

```
文本：    T   h   e   ·   t   r   a   n   s   f   o   r   m   e   r
输入 x：  T   h   e   ·   t   r   a   n   s   f   o   r   m   e   r
标签 y：      h   e   ·   t   r   a   n   s   f   o   r   m   e   r   …
（· 代表空格）
```

**每一个位置的标签，就是它后面那个字符。** 不需要任何人做任何标注工作。

> 这就是"自监督"的意思：**监督信号不是来自外部标注，而是来自数据自身的结构。**
>
> 代价是任务变简单了（"猜下一个字"听起来远不如"翻译"高级），收益是**数据量不再有上限**——见 §3.5。

### 3.3 一次前向，T 个位置同时监督

Transformer 训练时，一个长度为 $T$ 的序列是**一次**喂进去的，$T$ 个位置**同时**产出预测、**同时**算损失。

这件事能成立，全靠 §2.2 那道 mask：

```
位置 t 能看到的  →  x_0  x_1  …  x_t        （它左边的全部）
位置 t 要预测的  →  x_{t+1}                 （紧挨着它右边那一个）
```

两者严格不重叠——**模型永远看不到自己要预测的那个东西**。所以 $T$ 个位置可以并行监督，省下 $T$ 倍的时间。

> **注意：这不是差异，两边都有。** encoder-decoder 训练时，decoder 的每个位置也都有标签、也是并行监督的。
>
> 真正的差异只有一条：**监督的是不是同一条序列**（见 §3.4）。

### 3.4 x 和 y：同源还是两份

| | encoder-decoder | decoder-only |
|---|---|---|
| 要喂进去的东西 | **三份**：源句（给 encoder）、目标句（给 decoder 当输入）、目标句右移（当标签） | **一份**：文本本身 |
| x 和 y 的关系 | 来自**两份不同的数据** | **同一份数据的两个错位切片** |

在 decoder-only 里，"输入"和"标签"根本不是两种东西——**它们是同一段文字的两个视角**。

> 这个性质看起来平淡，但它是下一节那条推论的直接来源。

### 3.5 推论：这条差异决定了模型能长多大

**自监督 = 训练数据没有上限。**

| | 数据从哪来 | 全世界有多少 |
|---|---|---|
| 平行语料（翻译） | 人工翻译 | **有限**——高质量的量在千万到亿级句子的量级，再往上边际成本极高 |
| 单语文本（续写） | 互联网上的一切 | **没有上限**——网页、书、代码、论坛，全都能直接拿来用 |

> **这才是 decoder-only 真正的优势所在：它换的不是零件数量，是"能吃多少数据"。**

而在这条路上，**数据量就是天花板**。这就回答了 §1.4 留下的那个问题：为什么读得最少、理解任务最绕的 decoder-only，反而成了通吃的那一个。

## 4. 生成流程

### 4.1 先记住一个落差：训练并行，推理串行

**同一台机器，两种运行模式。**

```
训练：整个序列 ──一次前向──► T 个位置的预测（并行，§3.3）
推理：一个 token ──前向──► 下一个 token ──拼回去──► 再前向 ──► …
      （串行，第 t 步的输出变成第 t+1 步输入的一部分）
```

**这个落差是后面所有"生成"话题的舞台**，也是"训练指标很好、一生成就崩"这类现象的根源。

### 4.2 encoder-decoder 的生成：编码一次，解码多次

翻译一句话时：

```
① 源句进 encoder，【只跑一次】，得到整句的表示，放在那儿备用
② 手里有一串 token（一开始只有起始符）
③ 整串喂进 decoder 跑一次前向 —— 每一层都是
   masked self-attention → cross-attention → FFN
④ 取【最后一个位置】的打分
⑤ 归一化成概率分布，采一个 token，拼到序列末尾
⑥ 回到 ③，直到吐出终止符
```

注意 ① 和 ③ 的区别：**源句的编码是"一次性的"，目标词的解码是"一轮一轮的"。**

因为源句不会变——它的表示算一遍就够，之后每一轮都只是去查同一个结果（这正是 cross-attention 的用法）。而目标句每多一个词，就得多跑一轮。

### 4.3 decoder-only 的生成：只有接龙

没有"编码"这个阶段——原因和 §2.1 删掉 encoder 是同一条：**没有第二条序列要读**。

剩下的每一步都只做一件事：

```
① 手里有一串 token（一开始是提示词）
② 整串喂进去，跑一次前向
③ 只取【最后一个位置】的打分
④ 归一化成概率分布，从里面采一个 token
⑤ 把这个 token 拼到序列末尾
⑥ 回到 ②，直到吐出终止符 / 到达长度上限
```

**第 ③ 步是这里唯一需要想一下的地方：为什么只要最后一个位置？**

因为位置 $t$ 的预测只依赖它左边的内容（§2.2 那道 mask）。前面那些位置的预测，预测的是**它们各自右边那一个**——而那些位置早就有了正确答案（就是你当初喂进去的提示词），模型对它们的预测**毫无用处**。

> **唯一"还没有答案"的位置，就是最后一个。**

**两条路并排看：**

| | encoder-decoder | decoder-only |
|---|---|---|
| 第一步 | 源句过 encoder，**只做一次** | ——（没有这一步） |
| 每一轮做什么 | decoder 一步，产出一个词 | 同左 |
| 上下文从哪来 | 已生成部分 **＋ 源句** | 只有已生成部分 |
| 停止 | `<eos>` | `<\|endoftext\|>`（要自己造，见 §4.4） |

> 这里还有个容易绕晕的点：**decoder-only 也需要"读"输入**（你给它的提示词它得看懂）。但它的"读"是**和"写"用同一套参数、在同一次前向里完成**的——这就是 §2.3 说的"masked self-attention 成了唯一的注意力"。它不需要一个独立的、只读的环节。

### 4.4 停止机制：一个必须**自己造**的符号

这是架构差异的一个直接产物，也是最容易在写代码时卡住的地方。

| | encoder-decoder | decoder-only |
|---|---|---|
| 终止符 | `<eos>`（End Of Sequence，序列结束） | `<\|endoftext\|>`（文本结束） |
| 哪来的 | **句子边界是语言单位**——翻译的对象本身就是一句完整的话，"说完了"有现成的位置可标 | **边界得自己划**——原始文本是一大坨，从哪儿切、在哪儿结束全是预处理时决定的 |

差别不在符号本身，而在**"结束"这件事有没有一个现成的位置可以依附**。

所以 GPT-2（Generative Pre-trained Transformer 2）必须在词表里**新注册一个特殊 token**，并在预训练时把它插到每篇文档之间。这样做的效果是：**让"该结束了"也变成一个正常的"预测下一个 token"任务**，模型就能和其他字符一样把它学出来。

> **换句话说：decoder-only 连"什么时候停"这件事，都得自己造监督信号。**

**另外还有一层保险，和终止符并用（不是替代关系）：** 即使有了终止符，工程上也必须再设一个"最多生成多少 token"的硬上限。因为终止符是**采样**出来的——模型给它 0.9 的概率，也仍有 10% 的机会不被选中；它只是"很可能"，不是"一定"。两层一起用才安全。

### 4.5 两边共有的坑（不是差异）

**训练时，模型看到的前缀永远是真的；推理时，它看到的是自己刚生成的。**

一旦某一步偏了，错误会沿着后续所有步骤累积放大——因为模型下一步的输入，已经是它自己的错误输出了。

这是 teacher forcing（训练时喂正确答案）带来的固有落差。**encoder-decoder 和 decoder-only 都有**，不是架构差异，但在这里留个印象——写生成循环时会真切地撞上它。

## 5. 位置编码的设计差异

### 5.1 两种方案各自的账

| | **正弦公式**（2017 原版） | **可学查表**（GPT-2） |
|---|---|---|
| 怎么来 | 拿位置号代进 $\sin/\cos$ 公式**现算** | 一张表，拿位置号**查行** |
| 有参数吗 | **零**，纯公式，不参与训练 | **有**，每个位置学一整个向量 |
| 长度上限 | **没有**——公式对任意位置都有定义 | **硬上限**——超过表长就无行可查 |
| 各位置独立吗 | **不独立**，由公式互相约束 | **完全独立**，各自学各自的 |
| **买到** | 零参数；任意长度都能算；自带一条"**处处相同的规则**" | **完全自由**：不预设位置该长什么样，让梯度按任务去定 |
| **付出** | 把"每个维度是几何间隔的正弦波"这个**猜测**刻进了架构 | 参数；**彻底丧失外推**；**必须先有数据才学得出来** |

关键差别在"各位置独立吗"那一行。正弦版本自带一条**处处相同**的规则——"往后挪 $k$ 位"在位置 5 和位置 500 处做的是同一件事（03 笔记 §9 的"平移 = 旋转"），训练范围内学会的读法原则上能平移出去。**但"公式能算出"不等于"网络真会用"**：网络其余部分全是在训练长度内拟合出来的，实践中单纯正弦外推到训练长度之外仍会明显掉点（03 笔记 §10 的冷水）。

可学版本则是 $N$ 个**互相独立**的向量：位置 5 和 6 之间没有任何约束保证"$6-5$"和"$5-4$"长得一样。这是**另一层**的问题——不是"外推学得不准"，而是"第 101 位该长什么样"这种事**根本无从谈起**：表里没有这一行。

（03 笔记 §10 从"论文为什么推荐正弦"的角度详细讲过这件事，那里用的是"量长度的直尺 vs 记住 101 个孤立长度"的比喻。这里反过来看：**什么条件下该选可学**。）

### 5.2 一个必须说清的澄清：这不是因果

看到"原版用正弦、GPT 用可学"，很容易顺手归因成"因为改成 decoder-only 了，所以位置编码也得改"。**这个归因是错的。**

**GPT-2 选可学位置编码，和 decoder-only 没有因果关系。** 它是一个独立的决策，理由只有一条：**数据够多，付得起。**

- "需要数据才学得出来"——在 40 GB 文本面前根本不是问题
- "丧失外推"——训练语料的长度分布本身就很宽
- 换来的是"不把任何关于位置的猜测写进架构"

但这两件事**在同一个前提上交汇**：

```
decoder-only + 自监督   →   能吃掉海量无标注文本
                                  ↓
                            数据量爆炸
                                  ↓
                  "可学位置编码需要数据"这个代价  →  付得起
```

**是同一个前提的两个后果，不是一条因果链。**

这一点分清很重要——否则会推出"凡是 decoder-only 就该用可学位置编码"这种错误结论。事实上后来的模型大量使用**旋转位置编码**（RoPE，Rotary Position Embedding），它同样是**拿公式现算**的（把位置编成一组旋转，作用在注意力的查询和键上），**不是**一张学出来的表。

### 5.3 我们后面会怎么做

04 笔记要读的 `mini_gpt.py` 走的是**可学**这条路——因为它整体是照着 GPT-2 的形态来的。

具体怎么实现（表建多大、怎么查、上限撞到了会怎样），是代码层面的事，留给 04 笔记。

## 6. 这笔账划不划算

| 付出的 | 挣到的 |
|---|---|
| **丧失长度外推**——位置表有硬上限，超过就无行可查 | **能吃下互联网上所有无标注文本** |
| **理解类任务要绕**——分类不能直接出标签，得包装成"续写 + 取某个位置的输出分布" | **同一个架构通吃所有任务**——理解类只需改写成续写形式，不用换架构 |
| **生成时只能单向看** | 推理只需一摞，不需要"先编码一次" |

**"训练/推理不一致"（§4.5）不在这张表里**——它是 teacher forcing 带来的，encoder-decoder 和 decoder-only **都有**，不是 decoder-only 付出的代价。

**三行里最要盯住的是第二行**：decoder-only 付出的最大代价不是"零件少了"，而是**它只会接龙**——所有"理解"任务都得先被改造成接龙的形式，才能用它。

那它为什么还是赢了？**答案 §3.5 已经给过：它换来的不是零件，是"能吃多少数据"。**

这正是「设计是被挣来的」的又一个实例：**decoder-only 的简单，是用"海量无标注文本"换来的。**

如果数据不够多（比如只有一个专用领域的小语料），这笔账未必划算——那时"两摞 + 一座桥"的强先验反而是优势，因为它把"输入和输出是两个域"这件事直接写进了结构里。

## 7. 落到代码：所以 `mini_gpt.py` 里你会看到什么

这篇笔记是一座桥，另一头必须落在 04 上。带着下面这些预期去读 `mini_gpt.py`，每一步都会对得上：

| 这篇笔记说的 | 04 里会看到 |
|---|---|
| 只有一摞，没有 encoder | 一个 `blocks`，那就是整台机器 |
| 没有 cross-attention | 每层只有两个子层，不是三个 |
| mask 是承重墙 | 一个上三角置 $-\infty$ 的**固定**矩阵（不参与训练） |
| 位置编码换了实现 | 一张可学的表，不是公式 |
| 标签从数据右移一格来 | 切窗口时 `x` 和 `y` 错开一格 |
| 训练并行、推理串行 | `forward` 一次算完；`generate` 是个循环 |
| 生成要**自己造**终止符 | 当前实现**没有**——只有"最多生成多少" |

> **最后一行是个诚实的提醒**：`mini_gpt.py` 是**最小骨架**，它把"停止机制"整个省掉了。所以你会看到生成总是跑满预设长度、**不会自己停**。
>
> 这不是 bug，是一个被刻意留下的、可以自己动手补的缺口——补上它只需要在词表里加一个特殊符号、在预训练数据里插进去、再在生成循环里判断一次。
